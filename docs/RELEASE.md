# 릴리스 전 점검

Phase 5 까지 코드는 다 들어갔지만, 그것만으로 서비스를 열 수는 없습니다.
이 문서는 **코드로 끝나지 않는 항목**을 모아 둔 것입니다.

---

## 1. 법무 검토 — 열기 전에 반드시

`consent_documents` 에 들어 있는 다섯 문서는 모두 버전이 **`1.0-draft`** 입니다.
개발용 초안이고, 법률 검토를 받은 적이 없습니다.

| 문서 | 상태 |
|---|---|
| 서비스 이용약관 | 초안 |
| 개인정보 처리방침 | 초안 |
| 민감정보(건강정보) 수집·이용 동의 | 초안 |
| 검진 결과지 자동 판독 처리 위탁 동의 | 초안 |
| 마케팅 정보 수신 동의 | 초안 |

검토를 마치면 **기존 행을 고치지 말고 새 버전을 추가**하세요. 문서를 덮어쓰면
사용자가 실제로 동의한 내용이 사라져 동의 이력이 근거로 쓸 수 없게 됩니다.

```sql
-- 옛 버전을 내리고 새 버전을 올린다
update public.consent_documents set retired_at = now()
where kind = 'privacy_policy' and version = '1.0-draft';

insert into public.consent_documents (kind, version, title, body, is_required)
values ('privacy_policy', '1.0', '개인정보 처리방침', '...', true);
```

새 필수 문서가 생기면 `has_required_consents()` 가 false 가 되고, proxy 가
기존 사용자를 동의 화면으로 다시 보냅니다 — 재동의가 자동으로 걸립니다.

특히 확인이 필요한 지점:

- **민감정보 별도 동의** — 개인정보보호법 제23조. 일반 동의와 분리되어 있는지
- **처리 위탁** — 검진 결과지가 Anthropic API 로 전송됩니다. 수탁자·위탁업무
  범위가 처리방침에 명시되어야 합니다
- **국외 이전** — 위 API 는 국외에 있습니다. 별도 고지 항목입니다
- **의료기기 해당 여부** — 이 서비스는 판정·진단을 하지 않도록 만들어져 있습니다
  (`src/lib/metrics/status.ts` 의 라벨은 정상/주의/범위 밖/판정 기준 없음 뿐).
  이 선을 넘는 기능을 추가하기 전에 반드시 재검토가 필요합니다

## 2. 환경 변수

`.env.example` 을 그대로 따르되, 운영에서 빠지면 안 되는 것들:

| 변수 | 없으면 |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | 복약 알림 발송과 **계정 삭제**가 동작하지 않음 |
| `CRON_SECRET` | 알림 발송·Storage 정리 엔드포인트가 503 으로 닫힘 |
| `ANTHROPIC_API_KEY` | 검진 자동 판독만 꺼짐 (업로드·수동 입력은 정상) |
| `FOOD_API_KEY` | 음식 검색만 꺼짐 (직접 입력은 정상) |
| VAPID 키 3종 | 복약 알림만 꺼짐 |

계정 삭제는 service_role 이 필요합니다. 키가 없으면 화면에서 안내 문구가 뜨지만,
**탈퇴할 수 없는 서비스는 열면 안 됩니다.**

## 3. 스케줄러 등록

두 개의 배치가 있습니다. 둘 다 `Authorization: Bearer $CRON_SECRET` 이 필요합니다.

| 엔드포인트 | 주기 | 하는 일 |
|---|---|---|
| `POST /api/push/dispatch` | 5분 | 복약 알림 발송 (0006 주석 참고) |
| `POST /api/storage/cleanup` | 1일 | 삭제된 결과지 원본 파기 |

`storage_cleanup_queue` 는 앱이 정상 경로로 지우지 못한 파일을 담습니다.
소비자가 돌지 않으면 **파기했다고 표시된 파일이 실제로는 남습니다.**

## 4. 하지 않은 것

Phase 5 계획에 있었지만 이번에 넣지 않았습니다. 배포 환경 없이는 의미 있는
결과가 나오지 않는 항목들입니다.

- **부하 테스트** — 실제 인스턴스 규모·Supabase 요금제가 정해진 뒤에.
  가장 먼저 막힐 곳은 검진 판독(요청당 수십 초, 동시 실행 수 제한)입니다
- **모니터링·알럿** — 에러 추적, `checkup_extractions.status = 'failed'` 비율,
  푸시 발송 실패율. 특히 판독 실패율은 프롬프트 회귀를 잡는 유일한 신호입니다
- **백업·복구 훈련** — Supabase PITR 을 켜는 것과 복구를 해본 것은 다릅니다
