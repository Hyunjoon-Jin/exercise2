# 음식 영양성분 API 설정

Phase 2(식단)에서 음식 검색에 쓸 공공 API 발급 절차입니다.

> **키가 없어도 Phase 2 는 동작합니다.** 음식 직접 입력은 API 없이 되고,
> 검색 기능만 비활성화됩니다. 승인 대기 중에도 개발을 진행할 수 있습니다.

---

## 어느 포털을 쓸 것인가

같은 식약처 데이터를 두 곳에서 제공하는데, **인증키가 서로 다릅니다.** 한쪽에서
받은 키는 다른 쪽에서 쓸 수 없습니다.

| | 공공데이터포털 | 식품안전나라 |
|---|---|---|
| 주소 | data.go.kr | foodsafetykorea.go.kr |
| 데이터셋 | 식품의약품안전처_식품영양성분DB정보 | 식품영양성분 DB |
| 승인 | 개발계정 1~2시간 자동승인 | 회원가입 후 신청 |
| 개발 트래픽 | 하루 1,000건 (일부 10,000건) | 별도 확인 필요 |
| 운영 전환 | 운영계정 신청으로 상향 가능 | 별도 확인 필요 |
| 테스트 키 | 없음 | `sample` 키로 즉시 시험 가능 |

**공공데이터포털을 권장합니다.** 자동승인이라 빠르고, 다중 사용자 서비스로
키우려면 운영계정으로 트래픽을 올리는 경로가 명확합니다.

---

## 공공데이터포털 발급 절차

1. **회원가입** — <https://www.data.go.kr> 접속 후 가입.
   본인인증이 필요합니다 (휴대폰 또는 아이핀).

2. **데이터셋 찾기** — 검색창에 `식품영양성분DB정보` 입력, 또는 바로 이동:
   <https://www.data.go.kr/data/15127578/openapi.do>

3. **활용신청** — 오픈 API 탭에서 `활용신청` 클릭
   - 활용목적: `앱개발 (모바일, 솔루션 등)`
   - 상세 내용에 간단히 작성 (예: "개인 건강기록 앱의 식단 기록 기능에서
     음식 영양성분 조회에 사용")
   - 라이선스 표시 동의

4. **인증키 확인** — 보통 1~2시간 내 자동승인.
   `마이페이지 > 데이터활용 > 개발계정 > 활용신청 상세` 에서 확인합니다.

   **일반 인증키가 Encoding / Decoding 두 가지로 나옵니다.**
   서버에서 쿼리스트링에 붙일 때는 보통 **Decoding 키**를 쓰고 코드에서
   인코딩합니다. 둘 다 기록해 두시면 맞는 쪽을 골라 넣겠습니다.

5. **`.env.local` 에 입력**

   ```bash
   FOOD_API_PROVIDER=data.go.kr
   FOOD_API_KEY=발급받은_키
   ```

## 식품안전나라를 쓰는 경우

<https://www.foodsafetykorea.go.kr/api/howToUseApi.do> 에서 회원가입 후 신청합니다.

요청 형태가 경로 기반이라 구조가 다릅니다:

```
http://openapi.foodsafetykorea.go.kr/api/{인증키}/{서비스코드}/{형식}/{시작}/{끝}
```

서비스 코드는 두 개가 있습니다 — 신규 데이터는 **I0750**, 2023년까지의
과거 데이터는 **I2790** 입니다. 문서에서 어느 쪽이 현행인지 확인해 주세요.

```bash
FOOD_API_PROVIDER=foodsafetykorea
FOOD_API_KEY=발급받은_키
```

## 트래픽 제한이 설계에 미치는 영향

개발계정 기준 **하루 1,000건**은 다중 사용자 서비스에는 빠듯합니다.
사용자 한 명이 한 끼 기록하며 3~4번 검색하면 금방 소진됩니다.

그래서 Phase 2 는 **조회 결과를 `foods` 테이블에 캐시**합니다
(`supabase/migrations/0001_initial_schema.sql` 의 `foods`).

- 검색어로 먼저 로컬 `foods` 를 조회
- 없을 때만 공공 API 호출 → 결과를 `foods` 에 저장
- 이후 같은 음식은 API 를 타지 않음

한국인이 실제로 먹는 음식 종류는 수렴하므로, 초기 며칠만 지나면 API 호출은
급격히 줄어듭니다. 그래도 부족하면 운영계정으로 상향 신청하면 됩니다.

## 발급 후 알려주실 것

키를 받으시면 아래를 알려주세요. 실제 응답에 맞춰 클라이언트를 만들겠습니다.

1. 어느 포털에서 받으셨는지
2. 문서에 적힌 **요청 URL 전문** (엔드포인트 + 파라미터 목록)
3. **샘플 응답 JSON** 한 건 — 필드명이 문서와 다른 경우가 종종 있어
   실제 응답을 보고 맞추는 편이 확실합니다

> ⚠️ 인증키 자체는 붙여넣지 마세요. 대화 기록에 남습니다.
> `.env.local` 에만 넣으시면 됩니다.

### 참고: 이 개발 환경의 네트워크 제한

현재 컨테이너는 `openapi.foodsafetykorea.go.kr`, `data.go.kr` 등
정부 포털 호스트가 네트워크 허용 목록에 없어 직접 호출할 수 없습니다.
제가 여기서 실제 응답을 확인하려면 환경 설정에서 해당 호스트를
egress allowlist 에 추가해 주셔야 합니다.

추가하지 않으셔도 진행에는 문제없습니다 — 클라이언트를 어댑터로 만들고
고정 응답(fixture)으로 테스트한 뒤, 실제 호출 확인은 로컬에서 하시면 됩니다.
